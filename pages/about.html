ABOUT THE PROJECT

A small system data pipeline

Follow a process snapshot from this Mac to the browser.

How it works

  1. macOS → Shell. A read-only collector asks ps for process names and resource usage.
  2. Shell → CSV. The 20 highest-CPU processes become a timestamped, structured file.
  3. CSV → HTTP → JavaScript. The local server delivers the snapshot and the browser parses it.
  4. JavaScript → Dashboard. Tables, metrics and charts describe the collected records.
  5. launchd → Shell. An optional daily user agent refreshes the file at 09:00.

Reading the numbers

This is a snapshot of up to 20 busy processes, not an inventory of every process or a measure of total system load. CPU usage can exceed 100% for a process using multiple cores. Memory percentages describe each process’s share of physical memory.

Reload snapshot reads the CSV again; run the collector to measure newer data. The dashboard clearly labels demonstration data when the local file is unavailable.

Privacy and learning

Real process data stays in an ignored local CSV. Only fictional sample records are committed. The collector uses executable names/paths rather than full command arguments.
